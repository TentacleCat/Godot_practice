## 🎯 Kruskal 算法详解

### **1. 算法原理**

**最小生成树（MST）**：在加权图中找到连接所有节点的最小权重边集合

**关键特性**：
- ✅ 保证所有房间连通
- ✅ 使用最少的走廊（n 个房间只需 n-1 条走廊）
- ✅ 优先选择距离近的房间连接
- ✅ 不会产生环路（不浪费走廊）

---

### **2. 算法步骤**

```
步骤 1: 创建所有可能的边
  - 对于每对房间，创建一条边
  - 计算权重（曼哈顿距离）
  - 例如：4 个房间 → 6 条可能的边

步骤 2: 按权重排序
  - 从小到大排序（优先选择距离近的）
  - 例如：[5, 6, 7, 8, 9, 10]

步骤 3: 初始化并查集
  - 每个房间独立成一个集合
  - 例如：{A}, {B}, {C}, {D}

步骤 4: 遍历排序后的边
  - 如果边连接的两个房间不在同一集合：
    → 添加这条边
    → 合并两个集合
  - 否则跳过（避免形成环）
  
步骤 5: 终止条件
  - 选择了 n-1 条边
  - 所有房间连通
```

---

### **3. 可视化示例**

假设有 4 个房间：

```
初始状态：
    A(10,10)     B(30,10)
    
    C(10,30)     D(30,30)

所有可能的边（曼哈顿距离）：
A-B: |30-10| + |10-10| = 20
A-C: |10-10| + |30-10| = 20
A-D: |30-10| + |30-10| = 40
B-C: |10-30| + |10-30| = 40
B-D: |30-30| + |30-10| = 20
C-D: |30-10| + |30-30| = 20

排序后：
[A-B:20, A-C:20, B-D:20, C-D:20, A-D:40, B-C:40]

Kruskal 执行过程：

① 处理 A-B (20)
  集合：{A}, {B}, {C}, {D}
  A 和 B 不在同一集合 ✓
  → 添加边 A-B
  → 合并：{A,B}, {C}, {D}
  
    A───B
    
    C   D

② 处理 A-C (20)
  集合：{A,B}, {C}, {D}
  A 和 C 不在同一集合 ✓
  → 添加边 A-C
  → 合并：{A,B,C}, {D}
  
    A───B
    │
    C   D

③ 处理 B-D (20)
  集合：{A,B,C}, {D}
  B 和 D 不在同一集合 ✓
  → 添加边 B-D
  → 合并：{A,B,C,D}
  
    A───B
    │   │
    C   D

④ 已有 3 条边，4 个节点连通 ✓ 完成！

⑤ 跳过 C-D (20)
  C 和 D 已在同一集合 ✗
  → 跳过（避免环路）

最终结果：
- 选中的边：A-B, A-C, B-D
- 总权重：20 + 20 + 20 = 60（最优）
- 跳过的边：C-D, A-D, B-C
```

## 💻 类详解

### **RoomEdge.gd** - 房间边类

```gdscript
var room_a: Branch    # 第一个房间
var room_b: Branch    # 第二个房间
var weight: float     # 权重（曼哈顿距离）

func _init(a: Branch, b: Branch):
    # 自动计算曼哈顿距离
    var center_a = a.get_center()
    var center_b = b.get_center()
    weight = abs(center_a.x - center_b.x) + abs(center_a.y - center_b.y)
```

**为什么用曼哈顿距离？**
- 符合网格地图的特性
- 计算简单高效
- 反映实际走廊长度

---

### **UnionFind.gd** - 并查集

```gdscript
func make_set(item):      # 创建新集合
func find(item):          # 查找根节点（带路径压缩）
func union(item1, item2): # 合并集合（按秩合并）
func connected(item1, item2): # 判断是否连通
```

**优化技术**：
- **路径压缩**：查找时直接连接到根，加速后续查找
- **按秩合并**：将浅树连接到深树，保持树的平衡

**时间复杂度**：
- 单次操作：O(α(n)) ≈ O(1)（α 是反阿克曼函数，增长极慢）
- 非常高效！

## 📊 效果对比

### **之前（旧方法）**
```
问题：
❌ 连接所有相邻子节点
❌ 过多的走廊（2^n - 1 条）
❌ 许多走廊无法绘制（不对齐）
❌ 房间可能孤立

示例（4 个房间）：
- 尝试创建 7 条路径
- 实际绘制 2-3 条（其他不对齐）
- 某些房间可能无法到达
```

---

### **现在（Kruskal 算法）**
```
优势：
✅ 只连接叶子房间
✅ 最少的走廊（n-1 条）
✅ 所有走廊都能绘制（L 形）
✅ 保证所有房间连通

示例（4 个房间）：
- 创建 3 条走廊（最优）
- 全部绘制成功
- 总距离最短
- 100% 可达性
```

## 🔢 复杂度分析

| 步骤 | 时间复杂度 | 说明 |
|------|-----------|------|
| 创建边 | O(n²) | n 个房间，n(n-1)/2 条边 |
| 排序 | O(n² log n) | 排序所有边 |
| Kruskal | O(n² α(n)) | 遍历边 + 并查集操作 |
| 绘制走廊 | O(n × d) | n-1 条走廊，d 是平均距离 |
| **总计** | **O(n² log n)** | 排序占主导 |

**实际性能**（n = 16 个房间）：
- 创建边：120 条
- 排序：< 1ms
- Kruskal：< 1ms
- 总耗时：可忽略不计 ✅
